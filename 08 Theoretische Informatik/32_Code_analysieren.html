Schritte zählen: eine Schleife

Um die Laufzeit von Code zu bestimmen, zählst du, wie oft der Rumpf einer Schleife ausgeführt wird, und zwar abhängig von der Eingabegröße n. Konstanten und kleinere Terme fallen am Ende weg. Mit Schritt läuft der Code eine Anweisung weiter, mit Play von selbst.

Blättern: Pfeiltasten ← → oder die Buttons unten.

Verschachtelte Schleifen: multiplizieren

Steht eine Schleife in einer anderen, läuft die innere für jeden Durchlauf der äußeren komplett durch. Jedes Feld im Raster ist ein Durchlauf des inneren Rumpfs, also ein Paar (i, j).

Abhängige Schleifen: die Gaußsche Summe

Hier beginnt die innere Schleife bei i + 1. Sie wird mit jeder Zeile kürzer. Die Summe (n − 1) + (n − 2) + … + 1 + 0 ergibt nach Gauß n(n − 1)/2. Das ist knapp die Hälfte von n², also trotzdem O(n²).

Halbierende Schleifen: der Logarithmus

Halbiert eine Schleife in jedem Durchlauf die verbleibende Menge, ist sie nach ⌊log₂ n⌋ Durchläufen fertig. Probiere verschiedene n aus: Auch bei n = 1000 sind es nur 9 Schritte.

Versteckte Kosten

Ein Methodenaufruf ist kein einzelner Schritt. Steht er in einer Schleife, multiplizierst du die Durchläufe mit seinen Kosten. Diese Aufrufe kommen im Quiz vor (n = Anzahl der Elemente):

AufrufKostenWarum
list.Contains(x), list.IndexOf(x)O(n)durchsucht die Liste von vorne
list.Insert(0, x), list.RemoveAt(0)O(n)alle folgenden Elemente werden verschoben
list.Add(x), list[i], list.CountO(1)Add amortisiert: das Array wächst selten, dann aber auf das Doppelte
set.Contains(x), set.Add(x) bei HashSetO(1)Hashcode zeigt direkt auf das Fach (im Mittel)
dict[key], dict.ContainsKey(key)O(1)wie beim HashSet
dict.ContainsValue(v)O(n)Werte sind nicht gehasht, alle Einträge werden durchsucht
s += t bei stringO(Länge von s)Strings sind unveränderlich, der ganze Text wird kopiert
sb.Append(t) bei StringBuilderO(Länge von t)hängt an, ohne den bisherigen Text zu kopieren
OrderBy(...).ToList(), Array.Sort(a)O(n log n)sortiert jedes Mal alles
ToList(), ToArray(), a[..mid]O(n)kopiert die Elemente
Where(...).Count(), ElementAt(i)O(n)die Abfrage läuft bei jedem Aufruf neu durch die Quelle
Rekursion: Zeichne den Rekursionsbaum. Die Kosten sind Anzahl der Aufrufe × Arbeit pro Aufruf. Ein Aufruf mit n / 2 ergibt log n Ebenen, ein Aufruf mit n - 1 ergibt n Ebenen. Ruft sich eine Methode zweimal selbst auf, verdoppelt sich die Anzahl der Knoten mit jeder Ebene.
